Building Resiliency in Azure Service Bus

It’s no secret I’ve been a big fan of Azure for some time, but it’s also no secret that at times, I can get frustrated with Azure products missing some, how do I say it, “core” features that should really be out of the box.

One such feature is that Azure Service Bus does not natively have exponential backoffs with a retry.

Oof. No retries built in? Seems strange. But of course, there is always the GitHub Issues graveyard to confirm not only that this feature doesn’t exist, but that Microsoft has no intention of building it. Here’s the GitHub issue from 2023.

When architecting “around” the issue, I explored all options. First, can we use a different Azure product? Well, we have…

Azure Event Grid does have an exponential backoff mechanism (documentation here). But Event Grid has a couple of drawbacks. Mainly, it changes the consumer side of the messaging to a “push” rather than a “pull”. This can cause havoc if you have locked-down firewalls because you now need to let through an awful lot of Microsoft IPs that may or may not be your actual Event Grid instance.

The other more pressing issue with Event Grid, at least for the organisation I was with at the time, is that Event Grid’s messages sitting in the queue are “opaque”. You cannot “peek” messages in Event Grid. So while you may know that there are messages sitting there waiting to be reprocessed, you cannot see the contents of these messages. Basically take that observability and throw it out the window. While you’re at it, throw out Event Grid because it’s not going to work for us here!

Other Azure queuing systems such as Storage Queues simply didn’t have the functionality we required. We go from “pub/sub” back to point-to-point messaging. Not acceptable. Out the window it goes.

How about switching to AWS? It’s an option, right? Or at least should always be considered. This was one that I had the biggest headache with. EventBridge from Amazon (documentation here) seemed to fulfil all our needs, including an inbuilt exponential backoff. But, we were a Microsoft shop. Ultimately, looking at the total cost of ownership, standing up a full AWS environment, with all the security and platform boilerplate around that, was simply not an option for us.
